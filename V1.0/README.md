## 1. 1.0 是什么

**低代码平台（Coze）上的 Agentic RAG 原型**：以《中华人民共和国民法典》单部法律为知识库，通过「意图识别 → 任务拆解 → 知识库召回 → 答案生成 → 安全校验」的工作流，把自然语言法律问题转成**法条引用 → 法理释明 → 实务指引**的三段式回答。

| 项 | 1.0 的实现 |
|---|---|
| 平台 | Coze（Persona / Prompt + Workflows + Knowledge Base + Plugins） |
| 知识库 | 《民法典》单部，OCR 导入，500 字定长切片 |
| 检索 | 平台内置 RAG，Embedding-V1，召回数 10 → 4，阈值 0.1 → 0.35 |
| 生成 | 意图 / 任务拆解 Doubao-1.5-pro，答案生成 Doubao-2.0-pro；另横向对比 DeepSeek V3.1、ERNIE 3.5 / 4.0 |
| 评测 | 人工 MOS **三分制（0–2）**，五维（准确性 / 相关性 / 完整性 / 简洁性 / 安全性） |
| 安全 | Prompt 约束 + 零召回强制熔断 + Function Calling 限制对话轮次 |
| 范围 | 20 题评测集（显性 60% / 隐性 25% / 可解释推理 10% / 对抗 5%），Gemini 反推应召回法条作黄金集 |

**1.0 已经做对的事**（2.0 全部继承）：从用户调研出发定义四场景理想态、构建分层评测集、用控制变量法做策略调优、逐条 Badcase 归因。**评测意识在 1.0 就存在**，2.0 做的是把它从「人肉逐条打分」升级为系统能力。

## 2. 1.0 的量化结果

| 指标 | 调优前 | 调优后 |
|---|---|---|
| 检索精确率 Precision | 0.44 | **0.63** |
| F1-score | 0.49 | **0.57** |
| MOS 单轮对话 | — | **2.00 / 2.00** |
| MOS 多轮对话 | — | **1.92 / 2.00** |

> ⚠️ **口径提醒**：1.0 是 0–2 分制，2.0 是 1–5 分制，**两组数字不可直接比较**。且 1.0 只覆盖民法典，2.0 扩到 6 部法，召回指标也不共基线。

**模型横评结论**（`策略调优/模型回答对比.xlsx`）：DeepSeek V3.1 / ERNIE 3.5 / ERNIE 4.0 平均 MOS 分别 1.35 / 1.64 / 1.67。DeepSeek 拒答率 >25% 但无根据回答率为 0（可靠性最高、依赖检索）；ERNIE 3.5 每题都答、低分答案多（误导风险）；ERNIE 4.0 综合最优。

## 4. 与 2.0 的关系

| 环节 | 1.0 | 2.0 |
|---|---|---|
| 评测 | 人工逐条打分、一次性 | 五分制 + LLM-as-judge + 校准门禁 + 回归脚本 |
| 检索 | 平台内置、500 字切片 | BGE-M3 双路 + 查询扩展 + RRF 融合、法条级切分 |
| 知识库 | 民法典单部 | 6 部法 1868 条 + 法理别名 1663 条 |
| 工程 | Coze 工作流 | Python 核心链路 + FastAPI + React 前端 |
| 安全 | Prompt 约束 | 引用溯源机器校验 + 知识边界自白 + 置信度门控 |

**设计主线**：把 1.0 里「靠 prompt 和人肉扛」的环节换成系统能力。完整升级对照见仓库根 [`README.md`](../README.md) 第 2 章，迭代史与仪器修正见白皮书。
