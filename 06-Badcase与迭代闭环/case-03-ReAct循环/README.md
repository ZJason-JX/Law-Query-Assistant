# case-03 · ReAct 循环检索

## 1. 现象

复合问题整题召回烂：id12（事业单位能否按劳动法办 + 解除怎么办）整题 mean **0.50**，把两半拆开单独查各 **1.00**——说明知识在库里，一次性召回拿不到。

## 2. 归因

单轮检索把复合语义压成一个向量，子问题互相稀释。「任务分解能拿的分」可以**提前量化**：拆开两半各 1.00，目标就是把 0.5 的分找回来。

## 3. 假设

证据充分性门控（JEV 判定）不足时，自动生成缺口查询追加检索（≤2 轮），比一次性召回能吃到更多分。

## 4. 预注册门禁

显性 ≥0.90 / 隐性 ≥0.70 / 对抗一票否决；复合切片单独切出来看（0.75 → 目标 ≥0.95）。

## 5. 实验结果

- v2 mean recall：**0.933 → 0.983**
- 复合切片：**0.75 → 1.00**
- 对抗 veto：**FAIL → PASS**
- 机制实证：id29 错误前提题 `false_premise = 0.94` → 纠错式重查 → 补回劳动合同法第 21 条 → judge **5.0 / 4.8**

## 6. 采纳或否决

采纳，升级为 S0–S5 状态机（意图路由 → 首轮检索 → 充分性门控 → 追加轮 ≤2 → 生成 → 引用校验）。每轮检索了什么见 [`query_expansion_trace.jsonl`](query_expansion_trace.jsonl)，e2e 跑批见 [`v22_react_live/`](v22_react_live/)（同步副本在 [`05-评测体系/v2/results/v22_react_live`](../../05-评测体系/v2/results/v22_react_live/)）。
