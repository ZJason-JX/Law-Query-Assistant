# 线上 ReAct 路径 vs 复放路径：逐条对比

对象：`pipeline.answer(react=True)` 实时跑 JEV 门控 + DeepSeek 缺口查询（`v22_react_live`），对照 `v21_react_e2e` 用 trace 复放的两次运行（r1/r2）。

## 0. 对比口径与混杂因素

- **相同**：评测集 dataset_v2（30 法律题）、离线固化的扩展变体、意图缓存 `intent_cache_v2.jsonl`、检索与 RRF 参数、生成模型 Doubao（temperature 0）、Qwen 评审与评审 prompt。
- **唯一的设计差异**：ReAct 的门控分数与缺口查询，复放组读 trace，线上组实时调用。
- **混杂因素 1（非设计）**：线上组跑在免责声明加入 prompt 之后，答案末尾多一行固定提示，可能小幅影响简洁性与 MOS；v21 两次运行没有这一行。
- **混杂因素 2**：Doubao 在 temperature 0 下本身有措辞级抖动（r1 与 r2 的 MOS 差即噪声底，见 §3）。

## 7. 结论

**1. 线上路径可用且与评测路径行为一致。** 33 条（含 3 条拒答）全部跑通，ReAct 元数据完整落盘。门控非常稳定：首轮 sufficient 平均漂移 0.012，30/30 与 0.5 阈值同侧；追加轮数 29/30 一致。

**2. 不稳定的是缺口查询的生成。** DeepSeek 在 temperature 0 下，缺口查询文本逐字一致仅 3/51，导致 top-10 集合一致仅 13/30（平均重合 9.0/10）。ReAct 的检索结果因此是一个随机变量，之前的“双跑一致”只验证了复放。

**3. 召回的两次采样：0.983（trace 那次）与 0.967（本次线上）。** 差异只来自一道题：回退 ['id9']，提升 无。id9 的公司法第 264 条未进线上 top-10，primary 1.0→0.5。两个样本都高于 v2 基线 0.933 和预注册线 0.96，但对 0.96 的余量只有 +0.007。**按预注册的“其余切片不回退”，线上这次的可解释推理切片 0.875→0.750 严格说已回退一格（id9 一道题）。**

**4. 对抗否决与复合切片稳定。** trap_primary 3/3 命中（含 id29 劳合法第 21 条），复合切片 1.00，两次一致。

**5. 生成质量差异在噪声量级。** MOS 4.607 对复放均值 4.710；逐题 MOS 平均绝对差 0.123，与同路径两次运行的噪声底 0.113 相当。相关性均分下降最多（4 道题由 5 降到 3），评审理由分两类：id16/18/21 是“未按三段式展开”，而这三题走的是单段直出的 statute_lookup 模板，属评审口径波动；id7 是“漏了劳动法第 19 条”，但该漏召回在复放组里同样存在、当时却给了 5 分，也是评审波动。四题都无法归因到线上路径本身。免责声明只在安全性里被正面提及，未见扣分。
