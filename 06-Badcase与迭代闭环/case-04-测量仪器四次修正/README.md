# case-04 · 测量仪器四次修正

## 1. 现象

评测结果本身不可信：同一批答案在不同轮评分中反复横跳，版本对比无法定结论。

## 2. 归因

四次修正逐一归因：

1. **融合实现偏离规格**：v0.3 宣称 RRF 但实际用了 best-rank 主键 → 改回 RRF 求和，并**回溯重判两个历史版本**。
2. **judge 知识边界**：qwen-plus 凭过时记忆，冤判「引用了反不正当竞争法 2025 版第 13 条」的正确答案——**judge 的世界知识与被评测系统的知识库不同步时，会系统性冤枉引用新法条的答案**（法律年年修订，此 bug 必然复发）→ 给 judge 注入语料清单后回溯重判。
3. **judge 上下文丢失**：判分没拿到完整检索上下文 → 修复 + 回溯重判。
4. **我方误判门控位置**：架构图把门控画错了位置 → 纠正；顺带发现真问题：门控 state 只给条号不给条文，测的是「题难」而非「缺证据」，列入 v3 议题。

## 3. 假设

测量仪器先于被测对象校准：judge 先过 ±1 一致率门禁（86.7%，Pearson 0.893）才能用来判分。

## 4. 预注册门禁

修正完成后**回溯重判**所有受影响的历史版本，历史分数与新分数同口径；校准数据入档。

## 5. 实验结果

- 融合实现改回 RRF 求和，v0.3 记为「实现偏离规格」，v0.6-RRF 为合规实现；
- judge 注入语料清单后，2025 版反法相关冤判清除，回溯重判完成；
- judge 校准：±1 一致率 86.7%、Pearson 0.893（数据见 [`05-评测体系/v2/results/judge_calibration`](../../05-评测体系/v2/results/judge_calibration/)）；
- 门控位置图纠正 + 「state 只给条号」列入 v3 存货。

## 6. 采纳或否决

四次全部采纳并回溯重判。核心教训：**LLM-as-judge 不是装上就能用的仪器，它的知识边界本身是缺陷类别**。

## 7. 改动了哪个阶段的哪个文件

- [`05-评测体系`](../../05-评测体系/README.md)：`judge_prompt.md`（注入语料清单 + 上下文修复）与评测脚本；校准数据见 [`05-评测体系/v2/judge_prompt.md`](../../05-评测体系/v2/judge_prompt.md)。
